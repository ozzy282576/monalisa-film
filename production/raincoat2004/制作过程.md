# 制作过程 · 《韩国雨衣杀手柳永哲：十个月，二十条人命》

照 [`新题目开工手册.md`](../../新题目开工手册.md)（狂犬病模式）做的第三部片子，
第二部露脸模式的片子（第一部是《雨夜屠夫林过云》）。
本文件记录：每一步对应哪个文件、踩到什么、还剩什么没做完。

分支：`arena/ef74e893-desktop-tutorial`　项目：`production/raincoat2004`　成片目标：180 秒 / 1920×1080 / 30 fps。

---

## 1. 选题与素材来源

- 用户上传的 40 镜 JSON 稿（`抖音文案/20261007-020848_粘贴的文案_20261007-020848.txt`）给出叙事骨架：
  雨夜开场 → 人物档案 → 目标转变 → 按摩店线索 → 抓捕与逃跑 → 审判与结尾。
- 用户的三条硬要求：**3D 动画视频（不是图片视频）、可以露脸（不同人物不同脸、同一人物同一张脸）、字幕大一点**。
- 事实核查：8 条公开来源（英文维基、NamuWiki、新浪《信息时报》2004-12-26、Newsweek 2021、
  Murderpedia 汇编的 2004 年报道、ELLE 2022、人民网 2017、Crime & Court 2024），逐句对照写进
  [`史实核对.md`](史实核对.md)。上传稿里有几处与公开报道不符（如「2003 年 9 月住宅杀人案」的
  细节、「警方通过多渠道寻找目标」等模糊说法），一律按公开报道改写。

## 2. 与上传稿的差异（用户稿 → 成片稿）

| 上传稿 | 成片 | 为什么 |
|---|---|---|
| 40 镜 × 5 秒 | 45 镜 × 4 秒规划网格（38 个 Agnes 镜头 + 7 张信息卡） | 本流水线是三分钟 45 镜 × 4 秒结构；镜头数变了，内容不变 |
| 「最后警察没有找到凶手身份」等模糊句 | 按公开报道写具体（并案延迟、号码线索、逃跑 12 小时） | 每句话都要能指到来源 |
| 未提受害者构成与规模 | 信息卡写「二十人」与「十一名女性在其住所失踪」 | 用警方确认口径，不用「至少 23 人 / 26 人」的传闻数字 |
| 结尾「他承认了多起案件」 | 一审死刑 → 最高法院维持 → 1997 年后未执行死刑 → 至今在押 | 判决链条完整，避免「已释放」的误读 |

## 3. 内容与闸门

```bash
python3 production/raincoat2004/build_story.py            # 唯一内容源 → story.json + audio/manifest.json
python3 production/face_cast.py check-prompts --project production/raincoat2004   # 露脸静态闸门
python3 production/raincoat2004/generate.py --validate    # 时间轴 / 提示词 / 配音 SHA
```

- 45 镜 = 38 agnes + 7 信息卡（S02 案件名片 / S11 凶手档案 / S18 目标改变 / S25 最初的判断 /
  S36 关键日期 / S41 判决 / S43 案件之后）；每个镜头只用一次，`make_edl` 有断言。
- 解说 6 段 741 字（含标点）；TTS 原始 160.99 s → `tighten_pauses.py` 收紧到 150.46 s（只剪静音），
  可用窗口 168 s，实际变速比 **0.896**。
- `CUTS` 按 `audio/clause-times.json` 的**分句起点 − 0.15 s** 重对，`clause_times.py --check-cuts` 全绿。

## 4. 露脸模式（本片重点）

- 三个虚构匿名角色：**C1 雨衣男（凶手）**、**C2 老刑警**、**C3 按摩店老板**；
  `cast.json` 里每人一条 ≥60 字的面容 token、一个固定 seed、一张定妆照。
  **不做任何真实人物的肖像还原**——凶手不是柳永哲本人的脸。
- 同一张脸跨镜头稳定靠三件事叠加：
  1. 提示词里**逐字节**照抄该角色的 face token（`build_story.py` 用 `{C1}` 占位符从 `cast.json` 注入，
     从根上避免手抄漂移）；
  2. **该角色所有露脸镜头共用同一个 seed**——`generate.py` 新增 `shot_seed()`：
     一镜只登记一个角色时用角色 seed（这一条是手册《露脸模式》的"更强的锁"，本片第一次真正接线）；
  3. C1 / C2 / C3 的**首次露脸镜头（S05 / S06 / S27）用定妆照做图生视频首帧**
     （`reference_image`，`generate.py` 的 `full_payload` 把 `image=[URL]` 传给 Agnes）。
- 单角色镜头：S05 / S06 / S27 / S32（C1 两次）。双人镜头 S35（C1 与 C2 同框）**只对 C1 锁脸**，
  老刑警在该镜只给背影——`face_cast.py` 的静态闸门会拦"一个镜头带两张 token"，所以这里按闸门规则设计。
- 两道闸门：`check-prompts`（生成前，已 PASS）＋ `check-frames`（出片后，已接进 `*-visual-qc.yml`）。

## 5. 生成与复审

- 38 个 Agnes 镜头，每镜 7 s / 24 fps / 1080p，创建节流 75 s，两个 worker 共享闸门（≈48 分钟排队）。
- 断点续跑：`results.json` 按请求哈希复用；改提示词只重做变了的镜头。

## 6. 本地冒烟测试（出片前）

沙箱没有 Agnes 素材，但整条 `render.py` 可以用假素材跑通：

```bash
bash production/raincoat2004/tools/smoke_render.sh 960 540
```

本片实测：46 段 EDL 全部渲染、7 张信息卡与片头/片尾卡排字复核通过（左右安全带无越界）、
成品音频实测 RMS −20.02 dBFS / 峰值 −1.63 dBFS / 静音占比 0.55 %，`status=audio_verified_cut`。
这一步的意义：把 `CUTS`、卡片、字幕、混音的问题在烧 Agnes 额度之前就暴露出来。
