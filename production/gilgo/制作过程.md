# 制作过程 · 吉尔戈海滩：披萨盒里的凶手

按 `新题目开工手册.md` 的步骤走，这里只记录**这一部片子特有**的决定、数据和坑。
时间均为 2026-09-21（沙箱 UTC+8）。

## 0. 需求

抖音横版三分钟悬疑科普解说：长岛吉尔戈海滩连环案（Rex Heuermann，「披萨盒杀手」）。
用户要求：无限科学式快节奏、四列分镜脚本（时间轴 / 口播 / 画面 / 音效）、
**动画成片必须由 Agnes 视频片段构成**（图片幻灯 / Ken Burns 动画被明确否决）、
**每个片段都是全新镜头，不复用**（第二轮反馈）。

## 1. 事实核查（先于一切）

沙箱能上网搜索。核心事实全部来自 AP / CBS / CNN / Newsday / NYT / People / USA Today / Guardian 等公开报道，
逐条写进 `story.json.sources`（15 条）。两个容易写错的点：

- 2026-04-08 认罪的是 **7 项谋杀罪**，第 8 名受害者（Karen Vergata）是当庭**承认**、未被起诉——解说只说「承认了八起命案」；
- 2026-06-17 已宣判终身监禁不得假释——用户提纲里的「面临终身监禁」按最新事实改成「被判终身监禁」。

## 2. 解说词与 TTS 内容审核

第一版试音文本里有「他怎么杀、怎么藏」，`add_voice` 直接被内容审核拦下。
整稿改成新闻语体（「命案」「受害者」「弃置」「地下室里发生了什么，只有他知道」），
六段全部通过 TTS 审核，也顺带符合抖音审核尺度。六段共 785 字（不含标点）。

## 3. 配音太长：只剪静音，不动一个字

voice-00 念完六段 201.7 秒；`render.py` 的可用时长是 168 秒（180 − 片头 0.6 − 片尾 6 − 5 个 1.08 秒间隔），
变速闸门只允许 0.86–1.10×。量了一下：≥0.35 秒的句间停顿一共 51 秒，这个声音在逗号、破折号后动辄停 0.8–1.2 秒。

写了 `tighten_pauses.py`：48 kHz 单声道、10 ms 块 RMS<0.01 判静音，片头留 0.15 秒、片尾 0.25 秒、句内 ≤0.35 秒，
在静音中间剪、5 ms 交叉淡化。结果 201.7 → **176.1 秒**，变速 **1.048×**，逐字不变。
原始 TTS 留在 `audio/raw/`，manifest 的 SHA-256 记的是收紧后的文件。

|---|---|---|---|

| N02 | 24.44 | 21.58 | 12 |
| N03 | 35.52 | 32.52 | 11 |
| N04 | 33.28 | 27.50 | 17 |

## 4. 切点怎么对：分句 → 静音段的动态规划

收紧后每个标点处都剩一个 0.35 秒的静音段，所以「分句边界 = 某个静音段起点」基本成立，
但 TTS 在长数字串（「百分之九十九点九六」）里会多停，静音段数 ≥ 分句数。
`clause_times.py` 用 DP 从静音段里挑单调路径，使每个分句时长最接近「按字数摊开的期望时长」（对数比平方和最小），
输出 `audio/clause-times.json`。`render.py` 的 `CUTS` 切点 = 目标分句前那个静音段的起点 + 0.15 秒。
写完还用脚本反查每个切点是否落在 [分句开始 − 0.40, 分句开始] 里，抓出两处手抄错的数字（N02 S13、N05 S30）。

## 5. 「不复用镜头」→ 45 镜 × 4 秒网格

第一版 30 镜里为了配合停顿复用了 7 个镜头（老宅、地下室、手机、皮卡……），用户要求每个片段都是全新镜头。
于是：

- `build_story.py` 重写为 **45 镜 = 38 Agnes + 7 信息卡**，按成片顺序编号，每镜只出现一次；
- 参考项目的校验写死 30 × 6 秒，本项目 `generate.py` 改成 `GRID_SECONDS=4`（45 × 4 = 180），Agnes 每镜仍请求 7 秒；
- `render.py` 的 `make_edl` 加了断言：CUTS 里出现重复镜头、或有镜头没用到，直接报错；
- 生成预算从 85 分钟提到 170 分钟（38 镜共享 75 秒创建间隔，光排队就要 48 分钟）。

成片里每镜 2.0–6.7 秒，**全片没有慢放**（`time_stretch` 全为 1.0）。

## 6. 出片前的离线冒烟测试

沙箱连不上 Agnes，但可以用 38 段 `testsrc2` 假素材 + 伪造的 `results.json`（哈希对得上）跑通整个 `render.py`：
46 段 EDL、7 张信息卡、字幕、混音、成品复测全部通过；抽帧看了 7 张信息卡 + 片尾卡 + 片头字幕的排版。
第一次跑就抓到一个真问题：N06 最后一镜从 24.2 秒到 176.2 秒要 9.7 秒，超过 7 秒素材的 1.33× 慢放上限——这才把结尾拆成两镜。

参考项目 `render.py` 里有几处**按参考片接触表写死的时间窗**（S17 只用前 2.0 秒、S25 前 2.7 秒、S12 前 2.15 秒、S02 裁切、S06 指纹叠图），
`new_topic.py` 不会帮你删，落到新项目里会悄悄把可用素材砍短甚至直接报「慢放过度」。
本项目改成了两个空表 `WINDOWS` / `TIGHTER_CROPS`，看完接触表再按需填。

## 12. 成片复检（run 35595800301 交付的第一版）与字幕时间轴修复

第一版成片（`e044820`，SHA-256 `7e220309…`）本地复检：1920×1080 / 30 fps / 180.0 s / H.264+AAC / 69.97 MB，
46 段（38 镜 Agnes + 7 张卡 + 片尾卡）、无复用；RMS −20.03 dBFS、峰值 −1.43 dBFS、静音 0.55 %。
按 EDL 每段抽中点帧拼成两张联络表逐段看过：画面、卡片、顶部片名/免责标签、底部字幕（关键词描黄）都在。

**发现一个必须返工的问题：字幕时间轴。** 云端 whisper `base` 模型对六章配音的字级覆盖率只有
N03 = 1.00 达标，其余五章 0.01–0.77，`render.py` 就退回到 `captions_for` 的"按字数比例 + 停顿吸附"估计。
把交付的 `caption-timing.json` 与 `audio/clause-times.json`（`clause_times.py` 用能量包络 DP 对出来的
分句边界）逐句比对：N03 两者相差 ≤ 0.14 s（说明 DP 边界和 ASR 词级时间是一致的），
而估计版的 N02 最多早 0.98 s、N06 早 0.93 s、N05 早 1.84 s——"披萨边上的 DNA""百分之九十九点九六"
这些关键句字幕会比人声早出一秒多。参考项目冷案 DNA 的 v2→v3 正是因为同类"字幕不同步"返工过。

修法（`render.py`）：新增 `captions_from_clause_times(row)`，字幕时间来源改成三级——
ASR 词级（覆盖率够且每句都对得上）→ **`audio/clause-times.json` 的 DP 分句边界** → 比例估计。
DP 边界文件在配音收紧后就已生成并被 `render.py` 的 45 个切点引用，所以字幕和切点现在共用同一套时间；
文本对不上（改过分句 / 音频时长变了）时函数返回 None 自动退回估计，不会静默错位。
本地用交付的 `narration-timing.json` 跑过：六章 103 句全部命中，文本与第一版逐句一致，只有时间变了。
