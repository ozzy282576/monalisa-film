# 《物理学撕碎的"意外"》

抖音竖版悬疑解说片。**123.1 秒 · 1080×1920 · 30fps · 23 幕**。

这是 `scripts/noire/` 这条产线目前唯一的完整成片，也是它的验收用例。

## 出片

```bash
python3 -m pip install --break-system-packages pillow numpy
npm install                       # 提供 ffmpeg / ffprobe，缺了会静默丢掉配音时长

python3 scripts/run_noire_video.py --mode plan      # 先看时长与调色分配，不出图
python3 scripts/run_noire_video.py --mode render    # 出片 → renders/noire.mp4
```

`--mode plan` 会报总时长和"配音：N/23"。**如果这个数不对，先看它**：ffprobe 不在时
时长会退回每幕最小值，全片悄悄短掉几十秒。

## 内容

一个雨夜坠楼案。妻子死于楼下，丈夫说她是擦玻璃时失足。老刑警没有先看尸体，
他先做了个实验：把一袋和死者等重的水从同一个窗台推下去，水袋落在墙根。
而她的首次触地点，离墙根 **4 米**。

从落点反推 —— `t = √(2y/g)`，`v = √(g·x²/2y)` —— 她离开窗户那一刻的水平初速度
是 **3.6 m/s**。一个体弱多病的女人跳不出这个距离，一个"推"也给不了这个速度。
那只剩一种可能：她是被抱起、甩出去的。

**本片根据真实办案方法改编，综合多起案件，不是任何单一真实案件。**

片中涉及的物理方法有出处，不是编的：

| 内容 | 出处 |
|------|------|
| 坠落点水平位移的验算方法 | Rizer 1965, *J. Crim. L. Criminology & Police Sci.* |
| 一到十米高度坠落平均水平位移 0.74 m | 《法医学杂志》2022 年 614 例高坠统计 |
| 立定跳远世界纪录 3.71 m | Tvervaag 1968 |

剧情是虚构的 —— 检索过多个真实案例，没有与剧本吻合的单一案件，这也是片子要标
"综合多起案件"的原因。取证与物理推理部分按真实方法写，案情本身是戏剧化的。

## 美术

23 幕母图由生图模型逐幕绘制，**在已有黑白稿上上色**而不是重画 —— 重画会挪动门框、
窗户和手的位置，23 幕累积下来人物连续性会崩掉。上色用图生图，锁死构图、动作、人脸
与墨线，只加颜色；逐幕配色跟着分级走（夜戏冷青、室内暖琥珀）。

`scripts/noire/inspect_frames.py` 用来审计上色进度。它统计的是**有色像素占比**：
均值饱和度会误判（带蓝色调的黑白图同样"饱和"，而刻意的单色夜景同样会被误杀），
实测未上色图恰好是 0%，已上色图都在 5% 以上。

```bash
python3 scripts/noire/inspect_frames.py        # 23 幕逐幕判定
```

## 调色

分级不是简单的"对比度 + 饱和度"。`scripts/noire/grade.py` 里是一条电影管线：

```
按幕测光 → 单调三次色调曲线 → smoothstep S 曲线 → 胶片黑位抬升
        → 青橙分离调色 → 鲜艳度 → 饱和度
```

几个当年踩过的坑，都写在代码注释里：

- **对比度不能用绕 0.5 的线性乘算。** 这些是雨夜画面，中位亮度只有 0.085；
  乘算只会越算越暗。曾把幕 01 的 P90 从 0.57 压到 0.31，动态范围腰斩 ——
  这就是"又暗又灰"的成因。
- **测光要取镜头实际取景框**（`t=0.5` 的裁切），不是整张母图。否则镜头推近到
  亮的角落时，画面就对不上分级目标。
- **对比度要用 smoothstep，不能用线性乘算。** 线性会硬切到 1.0，曾把一幕 9% 的
  画面压成死白。
- **暗角别太重。** 0.42 实测砍掉 45% 的 P90；现在 0.16，氛围交给分离调色和黑位。
- **偏色修不掉已有的颜色。** 结尾全黑幕的母图带一层深蓝底，加法色偏修不掉，
  得用 `shadow_desat`（暗部去色）。

**电影感 = 高对比 + 克制饱和，不是更亮更艳。** 中途一度把中位拉到 0.60、饱和度
1.22，结果变成廉价连环画的艳；现在中位 0.50–0.57、饱和度 1.00。

## 配音

23 幕里 22 幕有旁白（幕 02 是纯画面卡）。音色 `voice-00`。

`render.py` 按 `<幕号>.mp3` 自动发现 `voice/` 下的音频，不需要手工维护
`media.voice` 映射。时长由真实配音驱动：`max(min_duration, 配音时长 + padding)`。
