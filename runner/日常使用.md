# 本地 runner·日常使用

> 装完了（`bash runner/setup-runner.sh` 一路走到「注册完成」），接下来你就住在这里。
> 三分钟最短路径见同目录的 `README.md`，完整原理见仓库根目录 `转私有与自托管Runner手册.md`。

## 一、三个每天都在用的命令

```bash
bash runner/selfcheck.sh                              # 出片前自检这台机器，退出码 0 才开工
gh api repos/32r4e2q-hub/desktop-tutorial/actions/runners --jq '.runners[] | [.name,.status] | @tsv'
                                                      # 看 runner 是不是 online/Idle
tail -40 ~/actions-runner/run.log                     # 上次 job 的日志（后台进程方式跑在 WSL2 时）
~/watchdog.sh                                         # runner 不在了就现在拉起来（不用等 5 分钟）
cat ~/actions-runner/.watchdog-heartbeat              # 看门狗最后一次检查是什么时候
```

```bash
# 系统服务方式装过的话，用 systemd 那套管它
sudo ~/actions-runner/svc.sh status                   # 看它活着没
sudo ~/actions-runner/svc.sh stop                     # 想停机一阵子再出片，先停掉
sudo ~/actions-runner/svc.sh start                    # 开工前再拉起来
```

> 目录默认是 `~/actions-runner`，装的时候 `--dir` 改过就换成你的。

## 二、出一次片的正确姿势

1. 开着这台机器（自托管 runner 的代价就是**机器得醒着**）；
2. `bash runner/selfcheck.sh`，见到「可以出片」再往下；
3. GitHub → Actions → 解说短片出片 → `project` 填 slug，跑；
4. 跑完看 Billing → Actions 的分钟数：**没涨** = 真的在用自己的机器。

最后一步会把成片和实测报告**推回 `交付/`**，这一步怕网络抖（大陆连 github.com 时好时坏）。
脚本现在是「4 秒 TCP 探针 + 低速 30 秒让位 + 40 轮 × 15 秒」的快失败多试；万一还是全败，
**别以为白干了** —— 渲染和 `git add`/`commit` 都已完成，成片就在工作目录里：

```bash
cd ~/actions-runner/_work/desktop-tutorial/desktop-tutorial && git log --oneline -2
git push origin HEAD:main                       # 网络恢复后手动推，成片不会丢
cp 交付/*.mp4 /mnt/c/Users/Administrator/Desktop/   # 顺手留个底（任务结束后工作目录会被清）
```

## 三、八个坑（每个都真踩过）

| # | 坑 | 怎么绕 |
|---|---|---|
| 1 | **git 走到一半静默卡死**（HTTP/2 在国内网络下会停住还不报错） | workflow 里已经统一把 git 切到 HTTP/1.1 了；自己手动 `git clone/pull` 卡住就 `git config --global http.version HTTP/1.1` |
| 2 | **把仓库 clone 到 `/mnt/c`**（Windows 盘符下），IO 慢好几倍、出片明显变久 | 进 WSL 后 `cd ~` 再 clone，放 Linux 家目录 |
| 3 | **没装中文字体就出片**：render 报 `refusing to render missing glyphs` | `sudo apt-get install -y fonts-noto-cjk`，再 `fc-cache -f` |
| 4 | **模型每跑一次重下 500 MB** | 仓库变量 `WHISPER_CACHE_DIR` 要指向常驻目录（脚本 `--set-switch` 会帮你设）；不然每次 job 都落在 work/ 里白下 |
| 5 | **连不上 huggingface.co**（模型下不动） | 仓库变量 `HF_ENDPOINT=https://hf-mirror.com` 且 `HF_HUB_DISABLE_XET=1`（只设镜像不关 Xet，照样 401） |
| 6 | **旧注册挡路**：`config.sh` 报 `already configured`，`--replace` 部分版本不顶用 | 重跑 `bash runner/setup-runner.sh`（脚本现在会先 `config.sh remove` 再注册）；实在不行删掉 `~/actions-runner` 整个目录重来一遍 |
| 7 | **后台 runner 静默死掉**：没有 systemd 时它就一个后台进程，谁也不知道它什么时候没了；2026-09-20 实测 `run.log` 从 `02:51` 空到 `07:57`，这 5 小时里派发的出片任务全卡在 `Waiting for a runner to pick up this job...` | `setup-runner.sh` 现在会自动装**看门狗**：`~/watchdog.sh` + Windows 计划任务 `runner-watchdog`，每 5 分钟检查一次，掉了就拉回来。手动催：`~/watchdog.sh`；确认计划任务在：PowerShell 里 `schtasks /query /tn runner-watchdog` |
| 8 | **注册 token / remove token 别乱贴** | token 只在你自己机器上现场取、用完就 `unset`，**不要贴进任何聊天框**（包括和代理对话）；卸载或重注册会再用到 token，照着脚本提示去页面复制 |
| 9 | **判断 runner 死活时用错命令**：`pgrep -f Runner.Listener` 会把任何**提到**这个名字的进程算命中（你自己敲的 `grep`、包着它的脚本都算），于是"还活着"是假的；盯 `run.sh` 又反过来 —— 它已经把自己 exec 成了监听器，进程命令行里根本没有这个名字 | 只认监听器可执行文件：`pgrep -f 'bin/Runner\.Listener'`（看门狗和 setup 用的都是这一条） |

## 四、保活是怎么做的（没有 systemd 也能扛）

这台机器的 WSL 太老（`wsl --version` 都不认，< 0.67.6），`svc.sh install` 那条 systemd 路走不通，
所以保活靠**看门狗 + Windows 计划任务**：

| 部件 | 位置 | 干什么 |
|---|---|---|
| `watchdog.sh` | `~/watchdog.sh`（仓库里是 [`watchdog.sh`](watchdog.sh)） | 监听器不在就 `setsid nohup ./run.sh` 拉起来；用 `flock` 防重入；只在真动手时写日志 |
| Windows 计划任务 `runner-watchdog` | Windows 任务计划程序 | 每 5 分钟跑一次上面那个脚本，登录后自动生效 |

`bash runner/setup-runner.sh` 会自动装上这两件（在「没有 systemd」的分支里）。手动重装/换机器：

```bash
cp runner/watchdog.sh ~/watchdog.sh && chmod +x ~/watchdog.sh
```

```powershell
schtasks /create /tn "runner-watchdog" /sc minute /mo 5 /f /tr "C:\Windows\System32\wsl.exe -d Ubuntu -u runner -- /home/runner/watchdog.sh"
```

两个日志别看混：

```bash
tail -3 ~/actions-runner/watchdog.log        # 只有"动手了"才写（没注册 / 拉起成功 / 拉起失败）
cat ~/actions-runner/.watchdog-heartbeat    # 心跳：最后一次检查的时间，正常每 5 分钟更新
```

> 看门狗**不负责开机**：Windows 没登录时 WSL 起不来。所以机器得醒着、登录着，
> 电源设置里的「睡眠」建议设成「从不」。
